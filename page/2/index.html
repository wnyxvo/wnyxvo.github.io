C++标准库-并发：promise

发表于 2025-03-24 更新于 2025-03-27 分类于 C++
本文字数： 889 阅读时长 ≈ 1 分钟

std::promise 是 C++11 引入的标准库类模板，属于并发支持库的一部分，常用于线程间通信。它允许一个线程在将来的某个时间点向另一个线程传递一个值或异常，配合 std::future 使用（负责获取值或异常）。std::promise对象只能使用一次。

主要成员函数

构造函数

  • std::promise()：默认构造函数。
  • std::promise(const std::promise&) = delete：不可复制。
  • std::promise(std::promise&& other)：移动构造函数。

成员函数

  • get_future()：返回与当前 promise 关联的 future 对象，且只能调用一次。
  • set_value(const T& value)：设置共享状态的值，之后 future.get() 可获取该值。
  • set_value_at_thread_exit(const T& value)：在线程退出时设置值。
  • set_exception(std::exception_ptr p)：设置异常，future.get() 调用会抛出该异常。
  • set_exception_at_thread_exit(std::exception_ptr p)：在线程退出时设置异常。

析构函数

  • ~promise()：销毁 promise 对象。如果没有设置值或异常，关联的 future 调用 get() 会抛出 std::future_error。

std::future 的常用方法

  1. get()
    获取与 std::future 关联的结果。该方法会阻塞直到结果可用。
    • 如果计算成功完成，get() 返回结果。
    • 如果任务抛出异常，get() 会重新抛出该异常。
  2. valid()
    检查 std::future 是否有效，即它是否关联着一个有效的异步任务。
  3. wait()
    阻塞当前线程，直到异步操作完成。wait() 不返回结果，仅用于等待计算完成。
  4. wait_for() 和 wait_until()
    这两个方法用于等待异步操作在给定的时间内完成：
    • wait_for() 在指定的时间段内等待结果。
    • wait_until() 在指定的时间点前等待结果。

对象的生命周期：

  • 全局对象在程序启动时分配，结束时销毁。
  • 局部对象在进入程序块时创建，离开块时销毁。
  • 局部static对象在第一次使用前分配，在程序结束时销毁。
  • 动态分配对象：只能显式地被释放。

对象的内存位置：

  • 静态内存用来保存局部static对象、类static对象、定义在任何函数之外的变量。
  • 栈内存用来保存定义在函数内的非static对象。
  • 堆内存，又称自由空间，用来存储动态分配的对象。

动态内存和智能指针

C++ 使用 new 和 delete 进行动态内存分配：

问题：

  1. 手动管理内存容易出错，忘记 delete 会导致 内存泄漏。
  2. 异常安全性差，如果 new 分配失败会抛出 std::bad_alloc。
  3. 容易发生悬垂指针（dangling pointer），如 delete 之后仍访问。

解决方案：使用智能指针！智能指针的行为类似常规指针，但负责自动释放所指向的对象。智能指针也是模板，在创建智能指针时需要指定指针指向的类型。

shared_ptr和unique_ptr都支持的操作：

操作 解释
shared_ptr<T> sp unique_ptr<T> up 空智能指针，可以指向类型是T的对象
p 将p用作一个条件判断，若p指向一个对象，则为true
*p 解引用p，获得它指向的对象。
p->mem 等价于(*p).mem
p.get() 返回p中保存的指针，要小心使用，若智能指针释放了对象，返回的指针所指向的对象也就消失了。
swap(p, q) p.swap(q) 交换p和q中的指针

std::shared_ptr

作用：多个 shared_ptr 可以共享同一块资源，使用引用计数来管理对象的生命周期。

头文件：#include <memory>

make_shared

提供的参数列表必须与类型的某个构造函数想匹配。

通常，std::shared_ptr<T> 需要存储两部分数据：

  1. 实际的对象 T。
  2. 引用计数控制块（Control Block），它管理引用计数 use_count 以及可能的 deleter。

但shared_ptr 它一次性调用 malloc，分配一个足够大的内存块。

std::make_shared 适用于任何可构造的类型，自动调用构造函数并安全管理内存。

直接管理内存

使用动态内存的三种原因：

  • 程序不知道自己需要使用多少对象（比如容器类）。
  • 程序不知道所需要对象的准确类型。
  • 程序需要在多个对象间共享数据。

用 new 动态分配和初始化对象：

  • new无法为分配的对象命名（因为自由空间分配的内存是无名的），因此是返回一个指向该对象的指针。
  • 一旦内存耗尽，会抛出类型是bad_alloc的异常。

用 delete将动态内存归还给系统。

  • 接受一个指针，指向要释放的对象。
  • delete后的指针称为空悬指针（dangling pointer）。
  • 释放数组时：delete []arr_name

使用 new 和 delete 管理动态内存存在三个常见问题：

  • 1.忘记delete内存。
  • 2.使用已经释放掉的对象。
  • 3.同一块内存释放两次。

概述

泛型算法 是指可以与 不同类型的数据 结合使用的通用算法，主要依赖 模板（Template） 机制实现。C++ 的标准库（STL）提供了一系列 基于迭代器的泛型算法，如 std::sort、std::find、std::for_each 等。C++ STL 的泛型算法主要在 <algorithm> 和 <numeric> 头文件中定义。

  • 泛型算法本身不执行容器操作，只是单独依赖迭代器和迭代器操作实现。
  • 除了少数例外，泛型算法都是对一个范围内（由迭代器指定）的元素进行操作。
  • 泛型算法永远不会改变底层容器的大小。算法可能改变容器中保存的元素的值，也可能在容器内移动元素，但不能直接添加或者删除元素。

初识泛型算法

只读类算法

一类算法只会读取输入范围内的元素，而不改变元素。如find()和accmulate()。

  • 第三个参数作为求和的初值，同时也指定了函数中使用哪个加法操作符和返回值的类型。同时注意一些类型可能没有默认的加法操作，如 const char*。
  • 对于只读取不改变元素的算法，通常使用cbegin()和cend()。
  • 默认第二个序列至少和第一个序列一样长
  • 两个序列中的元素类型不必一样

写容器元素的算法

泛型算法不会执行容器操作，它们自身不可能改变容器的大小。

泛型算法不会检查写操作是否超出范围。如fill_n(vec.begin(), 10, 0)，但这是个空的容器。

fill

  • fill： fill(vec.begin(), vec.end(), 0);
  • fill_n： fill_n(vec.begin(), 10, 0);

常常使用back_inserter 来创建一个迭代器，作为算法的目的地址使用。

顺序容器概述

概述

顺序容器（sequential container）：为程序员提供了控制元素存储和访问顺序的能力。这种顺序不依赖于元素的值，而是与元素加入容器时的位置相对应。它们以线性顺序存储和管理元素。

容器 底层结构 访问方式 适用场景
vector 动态数组 随机访问 O(1) 需要高效随机访问，元素增删较少的情况
deque 双端队列 随机访问 O(1)，前后插入快 需要在头部和尾部都能快速插入和删除
list 双向链表 双向迭代，访问 O(n) 需要高效插入、删除（O(1)），但不要求随机访问
forward_list 单向链表 单向迭代，访问 O(n) 仅需要前向遍历的链表，适合内存受限环境
array 定长数组 随机访问 O(1) 知道固定大小时，使用比 vector 更快
string 动态数组 随机访问 O(1) 用于字符串处理
  • 除了array固定大小外，其他容器都提供高效、灵活的内存管理。
  • 通常使用vector是最好的选择，除非你有很好的理由选择其他容器。
  • vector 适合随机访问多、插入删除少的场景。
  • deque 适合需要高效的头部和尾部操作的场景。
  • list 适合频繁插入和删除但不需要随机访问的情况。
  • forward_list 适合只需单向遍历并优化内存的场景。
  • array 适合大小固定、性能优化的情况。

容器库概述

在本节介绍对所有容器都适用的操作。

类型别名

类型别名 说明 示例（std::vector<int>）

const_reference 元素的常量引用类型 vector<int>::const_reference → const int&

iterator 迭代器类型（指向元素） vector<int>::iterator → std::vector<int>::iterator

迭代器

迭代器（Iterator） 是 C++ STL（标准模板库）中的一种对象，用于遍历容器（如 vector、list、map 等）。迭代器类似于指针，可以用于访问容器中的元素，并支持递增、递减等操作。

迭代器范围（Iterator Range） 是表示一段容器元素范围的方式，通常由起始迭代器（begin）和结束迭代器（end）组成。迭代器范围的约定是左闭右开（[begin, end)），即包含 begin 指向的元素，但不包含 end 指向的元素。

  • begin 指向范围的起始位置，end 指向超出范围的下一个位置。
  • end 不能被解引用（*end 是未定义行为）。

构造函数

名称 说明
默认 创建一个空容器
指定大小 创建一个指定大小的容器，默认初始化值
指定大小并初始化 创建一个指定大小并初始化所有元素的容器
范围构造 通过迭代器范围 [first, last) 构造新容器
拷贝构造 用另一个同类型容器构造新容器（深拷贝）
移动构造 通过 std::move() 接管另一个容器的数据，避免拷贝，提高性能
初始化列表 直接使用 {} 进行初始化
  • 只有顺序容器的构造函数才接受大小参数，关联容器并不支持。
  • array具有固定大小。当定义array容器时要指定大小和元素类型，大小也是类型的一部分。array支持拷贝或对象赋值操作，而内置数组不支持。
  • 和其他容器不同，默认构造的array是非空的。
  • 直接复制拷贝：将一个容器复制给另一个容器时，类型必须匹配：容器类型和元素类型都必须相同。
  • 使用迭代器复制：不要求容器类型相同，容器内的元素类型也可以不同。

赋值与swap

赋值运算符 =用一个容器的内容替换另一个容器的内容。左边容器的迭代器、指针和引用失效

array不支持{}赋值和assign，因为array要求赋值的两边的类型一致，这两种方式不能保证一致。

使用assign（仅顺序容器），时间复杂度：O(n)

swap() 交换，交换两个容器的内容，不涉及数据拷贝，只是交换指针或内部数据结构，性能极高（O(1)）。swap() 不会重新分配内存。

元素不移动意味着，除string外，swap() 交换后指向容器的迭代器、指针和引用不会失效。它们仍指向交换前指向的元素。swap() 成员函数、std::swap()（全局函数）；使用非成员版本的swap是一个好习惯。

特例，swap() 两个string会真正交换元素，因此耗时也就和元素个数成正比。

容器大小

除了forward_list外，每个容器类型都有三个与大小相关的操作：

  • size()返回容器中元素的数目。
  • empty() 返回 true 表示容器为空，false 表示容器有元素。避免 if (v.size() == 0)，推荐使用 if (v.empty())。
  • max_size()返回容器理论上可以存储的最大元素数量，具体数值依赖于系统和编译器。

对于vector 和 string还有个capacity() 返回当前分配的存储空间可容纳的元素个数，不一定等于 size()。

关系运算符

关系运算符两边的对象必须是相同类型的容器，且必须保存相同类型的元素。

==和!=判断两个容器的元素是否完全相等（大小相同 & 元素值相同）。<、>、<=、>=）都基于字典序比较。

lst.insert_after(p, il) 在迭代器p之后插入元素。由il指定初始化列表。
emplace_after(p, args) 使用args在p之后的位置，创建一个元素，返回一个指向这个新元素的迭代器。若p为尾后迭代器，则函数行为未定义。
lst.erase_after(p) 删除p指向位置之后的元素，返回一个指向被删元素之后的元素的迭代器，若p指向lst的尾元素或者是一个尾后迭代器，则函数行为未定义。
lst.erase_after(b, e) 类似上面，删除对象换成从b到e指定的范围。

改变容器大小

  • c.resize(n) ：调整c的大小为n个元素，若n<c.size()，则多出的元素被丢弃。若必须添加新元素，对新元素进行值初始化。

  • c.resize(n, t)：调整c的大小为n个元素，任何新添加的元素都初始化为值t

缩小容器，则指向被删除容器的迭代器、指针、引用都会失效。

容器操作可能使迭代器失效

在向容器添加元素后：

  • 如果容器是vector或string，且存储空间被重新分配，则指向容器的迭代器、指针、引用都会失效。
  • 对于deque，插入到除首尾位置之外的任何位置都会导致指向容器的迭代器、指针、引用失效。如果在首尾位置添加元素，迭代器会失效，但指向存在元素的引用和指针不会失效。
  • 对于list和forward_list，指向容器的迭代器、指针和引用依然有效。

在从一个容器中删除元素后：

  • 对于list和forward_list，指向容器其他位置的迭代器、引用和指针仍然有效。
  • 对于deque，如果在首尾之外的任何位置删除元素，那么指向被删除元素外其他元素的迭代器、指针、引用都会失效；如果是删除deque的尾元素，则尾后迭代器会失效，但其他不受影响；如果删除的是deque的头元素，这些也不会受影响。
  • 对于vector和string，指向被删元素之前的迭代器、引用、指针仍然有效。
  • 注意：当我们删除元素时，尾后迭代器总是会失效。
  • 注意：使用失效的迭代器、指针、引用是严重的运行时错误！
  • 建议：将要求迭代器必须保持有效的程序片段最小化。
  • 建议：不要保存end返回的迭代器。

vector 对象是如何增长的

vector和string在内存中是连续保存的，如果原先分配的内存位置已经使用完，则需要重新分配新空间，将已有元素从就位置移动到新空间中，然后添加新元素。为了减少这种代价，给vector和string实际分配的空间会比需求大。

管理容器的成员函数：

  • capacity()：在不重新分配空间的情况下，可以保存多少个元素。capacity()>=size()
  • reserve(n)：分配至少能容纳 n 个元素的内存空间。改变的是预先分配多大的内存空间。只有当 n 大于当前容量时，才会扩容。当 n 小于或等于当前容量，reserve什么也不做。调用reserve永远不会减少容量。
  • shrink_to_fit()：将capacity()减少到和size()相同大小。不保证一定退回内存空间。
  • shrink_to_fit只适用于vector、string和deque
  • capacity和reserve只适用于vector和string。

类相关的命名规范

以下命名规范来自谷歌开源项目风格指南：

类名：大写字母开始, 每个单词首字母均大写, 不包含下划线。避免缩写，除非是众所周知的术语。

类数据成员：一律小写, 单词之间用下划线连接，以下划线结尾

类常量： k 前缀 + PascalCase风格，如 kDaysInAWeek

类成员函数：PascalCase风格。其中的Getter 直接使用变量名的 PascalCase 形式、Setter 以 Set + PascalCase 形式命名。

定义抽象数据类型

类背后的基本思想：数据抽象（data abstraction）和封装（encapsulation）。数据抽象是一种依赖于接口（interface）和实现（implementation）分离的编程技术。

  • 封装（Encapsulation）：将数据和操作数据的代码绑定在一起，保护数据不被外界直接访问。
  • 抽象（Abstraction）：通过类定义抽象出具有共同特性的对象，提高代码的可重用性和可维护性。
  • 继承（Inheritance）和多态（Polymorphism）：实现代码的复用与动态绑定。

this

成员函数在内存中只有一份副本，函数需要知道是那个对象在调用。成员函数通过一个名为this的额外的隐式参数来访问调用它的那个对象。

  1. 类型与常量性：this指针的本质类型是 ClassName *const this，意味着这个指针本身是常量（你不能改变 this指向别的地址），但它所指向的对象的数据可以被修改。在声明为 const的成员函数（常函数）中，this指针的类型变为 const ClassName *const this，这意味着你不能通过 this修改对象的数据成员。常量成员函数的形参列表后面的const，改变了隐含的this形参的类型。

  2. 静态成员函数没有 this指针：因为静态成员函数属于类本身，而不属于任何一个特定的对象实例，所以它没有 this指针

    。这也意味着静态成员函数不能直接访问类的非静态成员。

  3. this指针的生命周期：this指针是作为成员函数的一个隐含参数存在的。

什么时候需要使用this：

  • 参数名和成员变量同名时
  • 返回对象自身（支持链式调用）
  • 在构造函数中调用类的其他成员函数

成员函数中的return *this; 解引用 this 以获取执行当前函数的对象。一个常量成员函数如果return *this，返回类型为常量引用。

常量成员

一旦初始化就无法改变；必须在类的构造函数中通过 初始化列表 进行初始化。初始化发生在构造函数体执行之前，通常通过初始化列表来进行。而发生在构造函数体内的是赋值。

静态常量成员：通常用于表示类的常量，而与某个特定对象无关，它们在整个类的范围内共享。初始化方式与静态成员一致。

静态成员

静态成员是属于类本身，而不是类的某个特定对象。它们的生命周期贯穿整个程序的执行周期，可以在没有创建对象的情况下访问。

静态成员变量的初始化通常在类外部进行。C++17 引入的 inline 关键字可以用来在类中定义静态成员变量。

静态成员函数不能访问非静态成员函数或非静态成员变量，因为它们没有类的实例来指向 this。可以基于const重载成员函数。

构造函数与析构函数

构造函数（Constructor）是 C++ 中一个特殊的成员函数，用于初始化类的对象。它在每次创建对象时被自动调用，用来为对象的成员变量分配初值。构造函数没有返回类型，且与类同名。构造函数在对象创建时执行，负责为对象分配内存和初始化数据。

构造函数的特点：

  1. 名称与类名相同。
  2. 没有返回类型。
  3. 可以有参数，也可以没有参数（即默认构造函数）。
  4. 可以重载，即同一个类可以有多个构造函数，只要它们的参数列表不同（构造函数重载）。

默认构造函数（default constructor）：

是指 可以在不提供实参的情况下被调用的构造函数。

  • 无形参构造函数（无参构造）（无明显形参，因为this的存在）
  • 所有参数都有默认值的构造函数

编译器创建的构造函数又被称为合成的默认构造函数。合成的默认构造函数中初始化类的数据成员的规则：

  • 如果存在类内初始值，就用它来初始化从成员
  • 否则，默认初始化（内置类型：未定义状态可能是任何值；类类型：调用默认构造函数）

如果程序中有使用默认构造的需求，而类没有用户声明的任何构造函数，则编译器会自动合成默认构造函数。

初始化列表（initializer list）是构造函数的一部分，用于初始化类的成员变量。对于需要构造的成员（如常量成员、引用成员、以及复杂类型的成员），初始化列表能够在对象创建时直接初始化这些成员，而不是先调用默认构造函数然后再赋值。

  • 初始化列表中的成员初始化顺序与它们在类中声明的顺序一致。
  • 初始化列表可以使用默认参数来简化代码。

析构函数（Destructor）是类的一种特殊成员函数，它在对象生命周期结束时自动调用，用于释放对象占用的资源。如果类使用动态内存分配或其他资源，应该在析构函数中释放它们，以避免资源泄漏。

**= default与 = delete**：显式要求编译器生成默认函数（= default），或禁止某些函数（= delete，如禁止拷贝）。

访问控制与封装

访问说明符（access specifiers）：

  • private：定义在 private后面的成员可以被类的成员函数访问，但不能被使用该类的代码访问； private隐藏了类的实现细节。
  • public：定义在 public后面的成员在整个程序内可以被访问； public成员定义类的接口。
  • protected：在继承中使用，允许派生类访问，但对其他外部代码隐藏。

class与struct的默认区别：使用 class关键字定义类时，其成员的默认访问权限是 private；而使用 struct时，默认访问权限是 public

封装的两个优点：

  • 确保用户代码不会无意间破坏封装对象的状态
  • 被封装的类的具体实现细节可以随时改变，而无须调整用户级别的代码

友元

友元机制是C++提供的一种有选择地打破封装的方法。它允许特定的外部函数或类访问当前类的所有私有（private）和保护（protected）成员

友元的三种形式：

  • 友元函数：授予一个非成员函数访问权限。
  • 友元类：授予另一个类的所有成员函数访问权限
  • 友元成员函数：只授予另一个类的某个特定成员函数访问权限，权限控制更精细

友元函数不是成员函数，因此不能使用 this 指针。声明在类中，在类外实现时不要使用 :: 来指定友元函数所属的类。

由于友元函数不是类成员，在类的用户使用前要声明友元函数（类外）。这个声明不是通用意义上的函数声明，仅仅指明了访问的权限。

友元的核心特性与使用要点：

  • 单向性：如果类A是类B的友元，并不意味着类B自动是类A的友元。友元关系不具有对称性
  • 不传递性：如果类A是类B的友元，类B是类C的友元，并不能推出类A是类C的友元
  • 不继承性：派生类不能继承基类的友元关系。如果类Base授予了友元关系，派生类Derived并不能因此访问Base的私有成员，除非Base显式将Derived也声明为友元
  • 声明与定义：友元声明不是函数或类的正式声明。通常在类内部进行友元声明后，还需要在外部提供该函数或类的正式声明，以确保其在当前作用域可见

友元函数常用于运算符重载，特别是当左侧操作数不是类的对象时，必须使用友元函数进行重载。

类的其他特性

可以在类中用typedef和using定义类型成员，用来隐藏一些实现细节，必须先定义再使用。

成员函数作为内联函数：

  • 在类的内部，常有一些规模较小的函数适合于被声明成内联函数。
  • 定义在类内部的函数是自动内联的。
  • 在类外部定义的成员函数，也可以在声明时显式地加上 inline。

可变数据成员（mutable data member）：mutable 关键字用于修饰类的非静态成员变量，使其可以在 const 成员函数内部被修改。这在需要在 const 语境中改变某些成员变量（如缓存、日志、统计信息等）时非常有用。不能用于 static 变量。

mutable 与 const_cast 的区别：

特性 mutable const_cast
作用范围 仅适用于类的非静态成员变量 可以移除任何 const 限制
适用场景 允许在 const 成员函数中修改变量（如缓存、日志） 允许对 const 对象执行修改（通常用于兼容旧代码）
安全性 安全，仅影响标记为 mutable 的变量 风险较高，可能导致未定义行为

类的作用域

析构函数再探

如果没有在析构函数的初始化列表中显示地初始化成员，则该成员会在构造函数体之外执行默认初始化。在析构函数体内执行的都是赋值操作。

有些成员必须在初始化列表中完成初始化，如 const 、引用类型和某种未提供默认构造函数的类类型。

构造函数初始值的顺序应该和成员声明的顺序保持一致。

如果一个构造函数为所有参数都提供了默认参数，那么它实际上也定义了默认的构造函数。

委托构造函数

Delegating Constructor 是一种允许在构造函数的初始化列表中调用同一类的另一个构造函数。

委托构造函数只能初始化列表中调用，委托构造函数不能出现在函数体内部。

如果委托构造函数形成循环，会导致无限递归，造成栈溢出（Stack Overflow）。

隐式的类类型转换

隐式的类类型转换：当 C++ 需要一个对象而你提供了不同类型的值时，编译器会尝试自动进行类型转换。这时会隐式调用类的构造函数，会出现几个问题： 意外的构造函数调用、不知道该调用哪个构造函数。

使用 explicit 关键字，用于防止隐式转换，主要用于单参数构造函数和类型转换运算符。

  • 只对一个实参的构造函数有效
  • 只能用于直接初始化

聚合类

字面值常量类

字面值类型（Literal Type）可以作为编译时常量，用于 constexpr 表达式。主要用于编译期计算，可以存储在只读数据段，减少运行时开销。

C++11 规定，如果一个类满足以下条件，它就是字面值常量类（Literal Class）：

  1. 至少有一个 constexpr 构造函数。
  2. 所有数据成员必须是字面值类型。
  3. 没有虚函数。
  4. 必须使用默认的析构函数（不能自己定义）。

如果变量在编译阶段就可以计算，就用 constexpr；如果变量在运行时才知道值，但仍然不希望它改变，就用 const。

函数基础

局部对象

在C++中，名字有作用域，对象有生命周期。

  • 名字的作用域是程序文本的一部分，名字在其中可见。
  • 对象的生命周期是程序执行过程中该对象存在的一段时间。

局部变量（local variable）：形参和函数体内部定义的变量统称为局部变量。它对函数而言是局部的，对函数外部而言是不可见的。局部变量的生命周期取决于定义方式。

自动对象：只存在于块执行期间的对象。当块的执行结束后，它的值就变成未定义的了。函数的形参就是一种自动对象，一旦函数终止，形参就会被销毁。

局部静态对象： static类型的局部变量，生命周期贯穿函数调用前后，在函数外仍然是不可见的。局部静态对象只在执行路径第一次经过对象定义语句时初始化，可以用来统计一个函数被调用的次数。

函数声明

参数传递

两种传参方式：值传递（passed by value）、引用传递（passed by reference）。建议使用引用传递代替指针形参。

使用引用避免拷贝。如果函数无须改变形参的值，最好将其声明为常量引用。被常量引用（const &）引用的参数在引用的作用域内不能被修改，但如果它本身是一个可变的变量，它仍然可以在其他作用域被修改。

当函数返回值较大或想要多个返回值时，可以使用引用形参返回，这样可以避免拷贝。

不能将普通引用绑定到 const 对象：所以要尽量使用常量引用。

数组形参

数组不允许拷贝和赋值，所以为函数传递一个数组时，实际上传递的是指向数组首元素的指针。

数组是以指针的形式传递给函数，函数一开始并不知道数组的尺寸。管理指针形参有三种常用技术：

  • 使用标记指定数组长度。要求数组本身包含一个介绍标记，如 C 风格字符串。
  • 使用标准库规范。传递指向数组首元素和尾后元素的指针。
  • 显示传递一个表示数组大小的形参。

可变形参

  • initializer_list
  • 省略形参符： ...，便于C++访问某些C代码，这些C代码使用了 varargs的C标准功能。

返回类型和 return 语句

  • 值的返回：返回的值用于初始化调用点的一个临时量，该临时量就是函数调用的结果。
  • 引用返回左值：函数的返回类型决定函数调用是否是左值。调用一个返回引用的函数得到左值；其他返回类型得到右值。
  • 列表初始化返回值：函数可以返回花括号包围的值的列表。（C++11）

返回数组指针

  • 声明一个返回数组指针的函数，函数的形参列表跟在函数名称后面且形参列表应该先于数组的维度

  • 尾置返回类型： 在形参列表后面以一个->开始：auto func(int i) -> int(*)[10]（C++11）

  • 使用 decltype： decltype(odd) *arrPtr(int i) {...}。这个要知道函数返回哪个数组。

内联函数

inline只是建议编译器优化，加或不加编译器都有可能优化或不优化。

内联函数与宏的区别：宏不安全

  • 宏是预处理指令，由预处理器完成文本替换。
  • 类型安全： 内联函数具有类型检查，宏则没有。内联函数会在编译时进行类型检查，而宏只是简单的文本替换，不关心类型。

内联函数的适用场景：短小的、频繁调用的函数

函数重载

重载：如果同一作用域内几个函数名字相同但形参列表不同，我们称之为重载（overload）函数。注意返回值不计入，当两个函数的名称和参数列表完全相同而返回值不同时，编译器会报错认为这是重复定义。

main函数不能重载。

重载和const形参：

  • 一个有顶层const的形参和没有它的函数无法区分。 Record lookup(Phone* const)和 Record lookup(Phone*)无法区分。

  • 相反，是否有某个底层const形参可以区分。 Record lookup(Account*)和 Record lookup(const Account*)可以区分。

  • 顶层const：表示指针本身是个常量；底层const：表示指针所指的对象是一个常量

  • 重载和作用域：若在内层作用域中声明名字，它将隐藏外层作用域中声明的同名实体，在不同的作用域中无法重载函数名。
