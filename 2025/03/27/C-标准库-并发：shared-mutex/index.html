C++标准库-并发：shared_mutex

发表于 2025-03-27 更新于 2025-03-29 分类于 C++
本文字数： 3.2k 阅读时长 ≈ 3 分钟

RAII 风格锁

std::shared_mutex

std::shared_mutex 是 C++17 标准库中引入的一种读写锁，用于在多线程环境中控制对共享资源的访问。它允许：

  • 多个线程同时读取（获取共享锁，也称为读锁）。
  • 一个线程独占写入（获取独占锁，也称为写锁）。

与 std::mutex 不同，std::shared_mutex 提供了更高的并发性，因为读者不会阻塞其他读者。

基本特性

  • 头文件 <shared_mutex>
  • 允许多个线程同时持有读锁（shared_lock）
  • 只允许一个线程持有写锁（unique_lock）
  • 适用于读多写少的场景
  • 不可递归，线程不能多次获取同一种锁
  • 需配合 RAII 包装类，如 shared_lock 和 unique_lock

接口函数

成员函数 功能
lock() 获取独占（写）锁，若锁被占用则阻塞
try_lock() 尝试获取独占锁，立即返回 true（成功）或 false（失败）
unlock() 释放独占（写）锁
lock_shared() 获取共享（读）锁，若锁被占用则阻塞
try_lock_shared() 尝试获取共享锁，立即返回 true 或 false
unlock_shared() 释放共享（读）锁

std::shared_lock

std::shared_lock 是 C++17 标准库中提供的RAII 风格锁管理器，专门用于管理共享（读）锁的生命周期。它与std::shared_mutex或std::shared_timed_mutex类型配合使用，允许多个线程同时获取共享锁，从而实现并发读取。

构造时加锁，析构时解锁（RAII机制）。

轻量级且可移动（可通过 std::move 转移所有权）。

构造函数

构造函数 说明
shared_lock() 默认构造，不加锁。
explicit shared_lock(mutex_type &m) 立即获取共享锁，阻塞直到锁可用。
shared_lock(mutex_type &m, std::defer_lock_t) 构造但不加锁，可延迟调用 lock() 加锁。
shared_lock(mutex_type &m, std::try_to_lock_t) 尝试获取共享锁，立即返回是否成功。
shared_lock(mutex_type &m, std::adopt_lock_t) 接管已加锁的共享锁，避免再次加锁。

成员函数

函数 功能
lock() 阻塞，获取共享（读）锁。
try_lock() 尝试获取共享锁，立即返回 true（成功）或 false（失败）。
unlock() 释放共享锁。
owns_lock() 判断当前是否持有锁，返回 true 或 false。
mutex() 返回底层使用的 mutex 指针。
release() 释放对 mutex 的所有权，不会自动解锁。

使用

  • 局部变量锁（作用域内自动释放）

  • 类成员变量锁（对象销毁时才释放）

基本用法

延迟加锁（defer_lock）

使用 defer_lock 标志来延迟加锁，之后手动调用 lock()。

尝试加锁（try_to_lock）

立即返回是否获取到锁，避免阻塞线程。

std::unique_lock

特性 std::lock_guard std::unique_lock
锁的所有权 不可转移或释放 可转移、可手动释放
锁模式 仅支持立即加锁 支持延迟加锁 (std::defer_lock)
锁操作灵活性 仅自动加锁/解锁 支持手动加锁/解锁 (lock()/unlock())
性能开销 无额外开销（更轻量） 略高（因支持更多功能）
适用场景 简单临界区保护 复杂锁管理（如条件变量、死锁避免）
