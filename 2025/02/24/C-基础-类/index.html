C++基础-类

类相关的命名规范

以下命名规范来自谷歌开源项目风格指南：

类名：大写字母开始, 每个单词首字母均大写, 不包含下划线。避免缩写，除非是众所周知的术语。

类数据成员：一律小写, 单词之间用下划线连接，以下划线结尾

类常量： k 前缀 + PascalCase风格，如 kDaysInAWeek

类成员函数：PascalCase风格。其中的Getter 直接使用变量名的 PascalCase 形式、Setter 以 Set + PascalCase 形式命名。

定义抽象数据类型

类背后的基本思想：数据抽象（data abstraction）和封装（encapsulation）。数据抽象是一种依赖于接口（interface）和实现（implementation）分离的编程技术。

  • 封装（Encapsulation）：将数据和操作数据的代码绑定在一起，保护数据不被外界直接访问。
  • 抽象（Abstraction）：通过类定义抽象出具有共同特性的对象，提高代码的可重用性和可维护性。
  • 继承（Inheritance）和多态（Polymorphism）：实现代码的复用与动态绑定。

this

成员函数在内存中只有一份副本，函数需要知道是那个对象在调用。成员函数通过一个名为this的额外的隐式参数来访问调用它的那个对象。

  1. 类型与常量性：this指针的本质类型是 ClassName *const this，意味着这个指针本身是常量（你不能改变 this指向别的地址），但它所指向的对象的数据可以被修改。在声明为 const的成员函数（常函数）中，this指针的类型变为 const ClassName *const this，这意味着你不能通过 this修改对象的数据成员。常量成员函数的形参列表后面的const，改变了隐 含的this形参的类型。

  2. 静态成员函数没有 this指针：因为静态成员函数属于类本身，而不属于任何一个特定的对象实例，所以它没有 this指针

    。这也意味着静态成员函数不能直接访问类的非静态成员。

  3. this指针的生命周期：this指针是作为成员函数的一个隐含参数存在的。

什么时候需要使用this：

  • 参数名和成员变量同名时
  • 返回对象自身（支持链式调用）
  • 在构造函数中调用类的其他成员函数

成员函数中的return *this; 解引用 this 以获取执行当前函数的对象。一个常量成员函数如果return *this，返回类型为常量引用。

常量成员

一旦初始化就无法改变；必须在类的构造函数中通过 初始化列表 进行初始化。初始化发生在构造函数体执行之前，通常通过初始化列表来进行。而发生在构造函数体内的是赋值。

静态常量成员：通常用于表示类的常量，而与某个特定对象无关，它们在整个类的范围内共享。初始化方式与静态成员一致。

静态成员

静态成员是属于类本身，而不是类的某个特定对象。它们的生命周期贯穿整个程序的执行周期，可以在没有创建对象的情况下访问。

静态成员变量的初始化通常在类外部进行。C++17 引入的 inline 关键字可以用来在类中定义静态成员变量。

静态成员函数不能访问非静态成员函数或非静态成员变量，因为它们没有类的实例来指向 this。可以基于const重载成员函数。

构造函数与析构函数

构造函数（Constructor）是 C++ 中一个特殊的成员函数，用于初始化类的对象。它在每次创建对象时被自动调用，用来为对象的成员变量分配初值。构造函数没有返回类型，且与类同名。构造函数在对象创建时执行，负责为对象分配内存和初始化数据。

构造函数的特点：

  1. 名称与类名相同。
  2. 没有返回类型。
  3. 可以有参数，也可以没有参数（即默认构造函数）。
  4. 可以重载，即同一个类可以有多个构造函数，只要它们的参数列表不同（构造函数重载）。

默认构造函数（default constructor）：

是指 可以在不提供实参的情况下被调用的构造函数。

  • 无形参构造函数（无参构造）（无明显形参，因为this的存在）
  • 所有参数都有默认值的构造函数

编译器创建的构造函数又被称为合成的默认构造函数。合成的默认构造函数中初始化类的数据成员的规则：

  • 如果存在类内初始值，就用它来初始化从成员
  • 否则，默认初始化（内置类型：未定义状态可能是任何值；类类型：调用默认构造函数）

如果程序中有使用默认构造的需求，而类没有用户声明的任何构造函数，则编译器会自动合成默认构造函数。

初始化列表（initializer list）是构造函数的一部分，用于初始化类的成员变量。对于需要构造的成员（如常量成员、引用成员、以及复杂类型的成员），初始化列表能够在对象创建时直接初始化这些成员，而不是先调用默认构造函数然后再赋值。

  • 初始化列表中的成员初始化顺序与它们在类中声明的顺序一致。
  • 初始化列表可以使用默认参数来简化代码。

析构函数（Destructor）是类的一种特殊成员函数，它在对象生命周期结束时自动调用，用于释放对象占用的资源。如果类使用动态内存分配或其他资源，应该在析构函数中释放它们，以避免资源泄漏。

**= default与 = delete**：显式要求编译器生成默认函数（= default），或禁止某些函数（= delete，如禁止拷贝）。

访问控制与封装

访问说明符（access specifiers）：

  • private：定义在 private后面的成员可以被类的成员函数访问，但不能被使用该类的代码访问； private隐藏了类的实现细节。
  • public：定义在 public后面的成员在整个程序内可以被访问； public成员定义类的接口。
  • protected：在继承中使用，允许派生类访问，但对其他外部代码隐藏。

class与struct的默认区别：使用 class关键字定义类时，其成员的默认访问权限是 private；而使用 struct时，默认访问权限是 public

封装的两个优点：

  • 确保用户代码不会无意间破坏封装对象的状态
  • 被封装的类的具体实现细节可以随时改变，而无须调整用户级别的代码

友元

友元机制是C++提供的一种有选择地打破封装的方法。它允许特定的外部函数或类访问当前类的所有私有（private）和保护（protected）成员

友元的三种形式：

  • 友元函数：授予一个非成员函数访问权限。
  • 友元类：授予另一个类的所有成员函数访问权限
  • 友元成员函数：只授予另一个类的某个特定成员函数访问权限，权限控制更精细

友元函数不是成员函数，因此不能使用 this 指针。声明在类中，在类外实现时不要使用 :: 来指定友元函数所属的类。

由于友元函数不是类成员，在类的用户使用前要声明友元函数（类外）。这个声明不是通用意义上的函数声明，仅仅指明了访问的权限。

友元的核心特性与使用要点：

  • 单向性：如果类A是类B的友元，并不意味着类B自动是类A的友元。友元关系不具有对称性
  • 不传递性：如果类A是类B的友元，类B是类C的友元，并不能推出类A是类C的友元
  • 不继承性：派生类不能继承基类的友元关系。如果类Base授予了友元关系，派生类Derived并不能因此访问Base的私有成员，除非Base显式将Derived也声明为友元
  • 声明与定义：友元声明不是函数或类的正式声明。通常在类内部进行友元声明后，还需要在外部提供该函数或类的正式声明，以确保其在当前作用域可见

友元函数常用于运算符重载，特别是当左侧操作数不是类的对象时，必须使用友元函数进行重载。

类的其他特性

可以在类中用typedef和using定义类型成员，用来隐藏一些实现细节，必须先定义再使用。

成员函数作为内联函数：

  • 在类的内部，常有一些规模较小的函数适合于被声明成内联函数。
  • 定义在类内部的函数是自动内联的。
  • 在类外部定义的成员函数，也可以在声明时显式地加上 inline。

可变数据成员（mutable data member）：mutable 关键字用于修饰类的非静态成员变量，使其可以在 const 成员函数内部被修改。这在需要在 const 语境中改变某些成员变量（如缓存、日志、统计信息等）时非常有用。不能用于 static 变量。

mutable 与 const_cast 的区别：

特性 mutable const_cast
作用范围 仅适用于类的非静态成员变量 可以移除任何 const 限制
适用场景 允许在 const 成员函数中修改变量（如缓存、日志） 允许对 const 对象执行修改（通常用于兼容旧代码）
安全性 安全，仅影响标记为 mutable 的变量 风险较高，可能导致未定义行为

类的作用域

析构函数再探

如果没有在析构函数的初始化列表中显示地初始化成员，则该成员会在构造函数体之外执行默认初始化。在析构函数体内执行的都是赋值操作。

有些成员必须在初始化列表中完成初始化，如 const 、引用类型和某种未提供默认构造函数的类类型。

构造函数初始值的顺序应该和成员声明的顺序保持一致。

如果一个构造函数为所有参数都提供了默认参数，那么它实际上也定义了默认的构造函数。

委托构造函数

Delegating Constructor 是一种允许在构造函数的初始化列表中调用同一类的另一个构造函数。

委托构造函数只能初始化列表中调用，委托构造函数不能出现在函数体内部。

如果委托构造函数形成循环，会导致无限递归，造成栈溢出（Stack Overflow）。

隐式的类类型转换

隐式的类类型转换：当 C++ 需要一个对象而你提供了不同类型的值时，编译器会尝试自动进行类型转换。这时会隐式调用类的构造函数，会出现几个问题： 意外的构造函数调用、不知道该调用哪个构造函数。

使用 explicit 关键字，用于防止隐式转换，主要用于单参数构造函数和类型转换运算符。

  • 只对一个实参的构造函数有效
  • 只能用于直接初始化

聚合类

字面值常量类

字面值类型（Literal Type）可以作为编译时常量，用于 constexpr 表达式。主要用于编译期计算，可以存储在只读数据段，减少运行时开销。

C++11 规定，如果一个类满足以下条件，它就是字面值常量类（Literal Class）：

  1. 至少有一个 constexpr 构造函数。
  2. 所有数据成员必须是字面值类型。
  3. 没有虚函数。
  4. 必须使用默认的析构函数（不能自己定义）。

如果变量在编译阶段就可以计算，就用 constexpr；如果变量在运行时才知道值，但仍然不希望它改变，就用 const。
