CUDA 中的异步API与同步API

CUDA 的 API 分为同步和异步两大类。简单来说，同步 API 会阻塞主机线程直到操作完成，而异步 API 会立即返回，让操作在后台执行。

特性 同步 API 异步 API
阻塞行为 阻塞调用线程，直到操作完成 立即返回，不阻塞调用线程
执行位置 主机线程等待 GPU 完成 GPU 异步执行，主机继续运行
典型函数 cudaMemcpy, cudaMemset cudaMemcpyAsync, cudaMemsetAsync
性能影响 主机和 GPU 不能并行工作 主机和 GPU 可以并行工作
流参数 通常没有流参数 必须有流参数
内存要求 可使用可分页内存 通常需要固定内存

同步 API

特点：

  1. 阻塞调用：CPU 线程会挂起，直到 GPU 完成该操作
  2. 简单易用：无需担心同步问
  3. 性能较低：CPU 在等待 GPU 时处于空闲状态

特点

  1. 非阻塞调用：立即返回，操作在 GPU 上异步执行

为什么异步内存传输必须使用固定内存？

核心原因：DMA 与内存页锁定。异步内存传输通过 DMA 直接在 GPU 和主机内存之间传输数据，绕过 CPU。

  1. DMA 需要物理地址连续性

    • DMA 引擎需要连续的物理内存地址来执行高效的数据传输
    • 常规的 malloc分配的内存是虚拟内存，物理页可能不连续
    • 操作系统随时可能移动物理页（页面交换），DMA 无法处理这种动态变化

  2. 内存页锁定

    cudaMallocHost分配的固定内存会：

    • 锁定物理页：防止操作系统将此内存换出到磁盘
    • 保证物理连续性：DMA 引擎可以获得稳定的物理地址
    • 允许直接访问：GPU 可以直接访问，无需 CPU 介入
    • 异步传输的底层流程
      • 调用 cudaMemcpyAsync
      • DMA 引擎获取固定内存的物理地址
      • DMA 直接从主机内存读取数据到 GPU
      • CPU 可以继续执行其他任务
      • 传输完成时，GPU 产生中断或通过事件通知

cudaMallocHost 与 malloc 的详细区别

内存类型对比

特性 malloc cudaMallocHost
内存类型 可分页内存 固定内存（页锁定内存）
物理连续性 不保证 保证物理页连续
可交换性 可被交换到磁盘 锁定在物理内存
DMA 访问 需要 CPU 介入 可直接 DMA 访问
分配速度 较快 较慢（需要锁定页）
传输性能 较慢（需临时锁定） 较快（直接 DMA）
异步传输 不支持 支持
系统影响 对系统影响小 占用物理内存，可能影响系统性能
释放函数 free() cudaFreeHost()

  4. 何时使用 cudaMallocHost？

    • 场景1：频繁传输的数据，如果需要在CPU和GPU之间频繁传输相同的数据

    • 场景2：流水线处理，使用双缓冲或多缓冲实现计算与传输重叠

  5. 何时使用 malloc？

    • 场景1：一次性或少量传输，如果数据只传输一次，同步传输即可

    • 场景2：CPU端大量数据处理， 如果数据主要在CPU上使用，很少传输到GPU
